# StemGen

**Turn any track into a Native Instruments `.stem.m4a`.** Pick a few audio
files, and StemGen separates each one into drums, bass, other and vocals with
[Demucs](https://github.com/facebookresearch/demucs), muxes the four stems plus
the mixdown into a Stem file with GPAC, and carries the original tags and cover
art across — ready for Traktor or any other Stems-capable player.

Runs on macOS and Windows, on your own machine. Nothing is uploaded anywhere.

This is a fork of [axeldelafosse/stemgen](https://github.com/axeldelafosse/stemgen)
with a small Qt front end around it.

---

## What it does

* **Separates** — `htdemucs` (Hybrid Transformer Demucs), on the GPU when
  there is one (CUDA or Apple MPS), otherwise on the CPU.
* **Keeps your quality** — 24-bit sources stay 24-bit; 32-bit is brought down
  to 24; everything is resampled to 44.1 kHz with SoX's very-high-quality
  resampler because that is what the model was trained on.
* **Writes real Stem files** — ALAC-encoded stems, the `stem-meta` atom with
  the standard four-colour layout, cover art and tags copied from the source.
* **Skips what is already done** — a file that is already a `.stem.m4a`, or
  that has one next to it, is left alone.

Accepted input: `.wav`, `.wave`, `.aif`, `.aiff`, `.flac`, `.mp3`.

## Install

Download the latest build from
[Releases](https://github.com/hdavid/stemgen/releases):

| | |
|---|---|
| **macOS** | `StemGen.dmg` — drag to Applications. |
| **Windows** | `StemGenSetup.msi` — a normal Next/Next/Install wizard. |

The Demucs model weights (~80 MB) are downloaded on first run into your torch
cache and reused afterwards.

### What you need

| | |
|---|---|
| **OS** | macOS 13 or newer, or Windows 10/11 (64-bit). |
| **ffmpeg + SoX** | On `PATH`. macOS: `brew install ffmpeg sox`. Windows: install both and add them to `PATH`. |
| **Disk** | ~1.5 GB for the app (most of it is torch). |

`mp4box` (GPAC 26.07) is bundled — you do not need to install it. On macOS it is a
static universal binary, so the app runs natively on Apple Silicon and Intel.

> If Homebrew is not installed yet:
> `/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"`

## Using it

1. Click **Start** and pick one or more tracks.
2. Watch the counter — it shows which track is being prepared, split, saved
   and cleaned, and how many were processed, skipped or failed.
3. The `.stem.m4a` lands next to the source file. The details pane at the
   bottom lists every processed track and any error at the end of the run.

The window has no title bar — drag it anywhere by its body, close it with the
× in the corner.

## Build from source

Requires Python 3.13 (pinned — Nuitka's 3.14 support is not ready yet) and
[uv](https://docs.astral.sh/uv/), which the Makefile bootstraps if it is not
already on `PATH`. Only `python3` is needed on a fresh clone. ffmpeg and SoX
must be installed to actually run the app (see above).

```bash
git clone https://github.com/hdavid/stemgen.git
cd stemgen

make venv      # create .venv with runtime + build + dev dependencies
make run       # run from source
make test      # unit tests
```

To build a distributable:

```bash
make build     # Nuitka compile → dist/StemGen.app (Windows: dist/StemGenApp.dist/)
make package   # wrap it: .dmg on macOS, .msi on Windows
make deploy    # macOS: build + install into /Applications, replacing the old copy
```

On Windows use `.\make.ps1 <target>` — same names, same behaviour, except
that uv has to be installed first (`winget install --id=astral-sh.uv -e`);
there is no bootstrap fallback there. `make help` lists everything.

Signing is optional: with no `DEVELOPER_ID_APP` in
`.env.local` the macOS build signs ad-hoc and still runs locally; copy
`.env.local.example` to `.env.local` to sign with a Developer ID and notarize.

Tag a commit `v*` and the GitHub workflows under `.github/workflows/` build
the `.dmg` and the `.msi` and attach both to the release.

### Layout

```
src/
  StemGenApp.py       entry point — the Qt window and worker thread
  stemgen.py          the pipeline: prepare → Demucs → Stem file → clean up
  ni_stem.py          Stem file creation around GPAC's mp4box
  metadata.py         tag and cover-art extraction
  layout.py           generated by pyuic5 (imports switched to PySide6) — do not edit by hand
  runtime.py          dev-vs-bundle detection, bundled-data paths
GPAC_mac/ GPAC_win/   mp4box shipped inside the app (macOS: static universal build, see scripts/build_mp4box_macos.sh)
GPAC_linux/           (kept for running from source on Linux)
assets/               icon, .dmg background
scripts/              build (Nuitka), packaging (.dmg / .msi), signing
tests/unit/           headless — no Qt, no ffmpeg, no model download
```
